# 개발용 합성 최소 샘플

실제 대회 안내나 제출물이 아닌 **직접 구성한 개발 전용 최소 시연 자료**다. 정상본, 누락본, 표현 변경본은 모두 같은 `before-submit-development-001` 가족이며 최종 독립 평가용 데이터로 분리할 수 없다. API 호출이나 모델 성능 측정은 수행하지 않았다.

`sources.json`은 페이지별 작성 원문이다. `truth.json`은 생성기·검사 결과에서 자동 생성하지 않고 요구사항과 근거를 직접 대조하여 작성한 **단일 작성자·AI 보조 정답 초안**이다. 사람 검수 완료나 복수 검수자 합의를 주장하지 않는다. 따라서 엄밀한 사람 작성 정답이 필요한 평가 전에는 사람이 검토·승인해야 한다.

| 파일 | 내용 |
|---|---|
| `pdf/guide.pdf` | 2페이지 안내문, 안정적인 R001~R005 기준의 출처 |
| `pdf/normal.pdf` | 적용되는 필수 하위 조건을 모두 설명한 2페이지 보고서 |
| `pdf/missing.pdf` | 정상본에서 API 출력 설명 한 문장만 삭제한 2페이지 보고서 |
| `pdf/paraphrased.pdf` | 제목과 표현을 바꾸고 정상본 의미를 유지한 2페이지 보고서 |
| `sources.json` | 문서 ID, PDF 상대 경로, 페이지 번호, 제목과 본문 원문 |
| `truth.json` | 기준 출처, 하위 조건, 보고서별 판정·정확 인용·위치·분량 측정 |

PDF 파일 첫 페이지가 1이다. 인쇄된 쪽번호로 위치를 추론하지 않는다. 분량 상한은 **전체 파일 2페이지**이며 표지·본문·참고문헌·부록·구현 화면을 모두 포함한다. 실제 대회의 화면 제외 규칙을 복제한 것이 아닌, 개발용으로 포함 범위를 완전히 정의한 별도 규칙이다.

R002는 `R002.input`과 `R002.output`을 모두 요구한다. 누락본에도 `AI API 사용계획`과 `입력과 출력` 제목이 남아 있다. 제목은 내용 증거가 아니므로 입력만 충족하고 출력은 `근거 미확인`, 상위 항목은 `부분 충족`이다. 검토 범위는 각 보고서의 1~2페이지이며 근거 미확인을 문서 전체의 부재 증명으로 일반화하지 않는다.

R003 구현 화면은 선택 사항이다. R004는 실제 개인정보 사용 시에만 비식별화 방법을 요구한다. 세 보고서 모두 실제 개인정보 미사용을 명시했다. 이 두 항목은 `applicability: not_applicable`, `status: null`로 구분하며 충족이나 누락으로 강제 변환하지 않는다. 적용 제외 근거는 `applicability_evidence`이고 요구 충족 근거인 `evidence`와 별개다. 조건 성립 여부 불명이나 실제 개인정보 사용 시나리오는 이번 최소 가족에 없다.

인용은 해당 PDF 페이지에서 정확히 존재해야 한다. 이는 문자열·위치 검증이며 의미 판정 정확도 검증과 별개다. R005의 보고서 자기 진술 인용은 보조 자료이고, 실제 충족 여부는 PDF 페이지 수와 `measurement`를 대조하여 확인한다.

API 폴더에서 재생성:

```sh
uv run python tools/generate_samples.py
```

프로젝트 환경이 없을 때는 PEP 723 메타데이터로 실행할 수 있다:

```sh
uv run tools/generate_samples.py
```

생성기는 `sources.json`만 읽고 `pdf/*.pdf`를 갱신한다. 정답 파일은 수정하지 않는다. ReportLab의 한국어 CID 폰트 `HYSMyeongJo-Medium`을 사용하며 PDF 뷰어에 따라 폰트 대체가 달라질 수 있다. 각 문장을 한 줄에 배치하고 페이지 넘침을 오류로 처리한다. PDF 재생성 후 pypdf로 모든 인용·페이지를 확인하고, Poppler 렌더링으로 한글 표시와 페이지 구성을 검토해야 한다.
