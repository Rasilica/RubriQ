# 빌링AI 연결

`/prepare`의 클라우드 윤문과 ‘요구사항 확인 후 AI 검사’에서 **빌링AI**를 선택한다. 빌링AI가 선택 모델의 공급사로 요청을 중계한다. RubriQ가 로컬에서 실행되더라도 이 기능은 외부 전송이며 빌링AI 크레딧이 사용될 수 있다.

## 사용하기

1. 빌링AI 계정에서 키를 발급받고 사용할 텍스트 모델을 확인한다.
2. 문서를 준비한 뒤 제공자에서 빌링AI를 선택한다. 모델 ID는 `gpt-5-4`, `claude-sonnet-4-6`, `gemini-2-5-flash`처럼 **공급사 접두사 없이** 입력한다. 이는 입력 예시이며 권장 모델·현재 계정 권한·지원 보장이 아니다. `openai/gpt-5-4`나 전체 URL은 RubriQ 입력에서 허용하지 않는다.
3. 설정에서 빌링AI 키를 한 번 등록하거나 해당 패널에 일회성 키를 입력한다. OpenAI·Google·Anthropic 직접 연결 키를 빌링AI 키 대신 사용하지 않는다. 등록한 키는 운영체제 보안 저장소에 보관하며 입력란을 비운다. 교체·삭제는 [API 키 설정](AI_SETTINGS.md)을 참고한다.
4. 윤문은 선택 문구를, 요구사항 추출은 안내문을 미리 확인하고 동의 후 실행한다. 보고서 검사는 요구사항을 먼저 확인·확정한 뒤 안내문·보고서·기준 범위를 별도로 확인하고 동의한다.
5. 원문 인용과 AI 판단을 직접 검토한다. 실패 후에는 범위를 다시 미리보고 동의해야 재실행할 수 있다. 자동 재시도나 다른 제공자로 자동 전환하지 않는다.

요구사항·보고서 검사는 [SEMANTIC_AI.md](SEMANTIC_AI.md), 선택 문구 윤문은 [CLOUD_AI.md](CLOUD_AI.md)의 원문 검증·한도·임시 결과 규칙을 그대로 적용한다. AI 기준과 검사 결과는 문서 보관에 포함되지 않는다.

## 연결 계약

보고서 검사 인용은 서버가 원문에서 만든 요청별 참조를 모델이 선택하고 서버가 실제 문구와 Unicode 범위를 확정한다. 이 wire 형식은 모델의 문자 수 계산·재작성 오류를 줄이기 위한 것으로, 검증 완료 인용과 보관 계약은 유지한다. 모델 응답 스키마는 보고서 검사에서만 인용 참조 형식으로 변환한다. 선택한 참조의 의미적 적합성까지 보증하지 않으며 출처·범위·원문 검증을 계속 적용한다.

- 제공자 ID: `billingai`. 기존 세션 API·헤더를 사용하며 일회성 키는 `X-AI-API-Key`로 로컬 서버에 전달한다. 저장한 키는 `use_saved_key: true`로 지정하고 서버가 읽는다.
- 서버 외부 호출은 고정 HTTPS `billing-ai.doubleze.ro`와 `Authorization: Bearer <키>`를 사용한다. 일반 윤문은 `POST /api/v1/chat/completions`, 요구사항 추출·보고서 검사는 `POST /api/v1/responses`를 사용한다. 사용자가 임의의 Base URL을 입력하지 않는다.
- 윤문 본문은 모델 ID, `system`/`user` 메시지, 출력 토큰 한도, `stream: false`다. 의미 검사는 `model`·`instructions`·`input`·`max_output_tokens: 8192`·`stream: false`와 `text: {format: {type: "json_object"}}`를 전달한다. Responses는 무상태 경로이므로 `store`와 `previous_response_id`를 보내지 않는다. 문서 파일이나 이미지를 업로드하지 않고 확인한 텍스트와 시스템 지침만 전송한다.
- 완료된 assistant 텍스트만 허용한다. 잘린 생성·거절·도구 호출·빈 응답·손상 응답은 오류로 처리하며 원문·키·공급사 오류 원문을 반환하지 않는다.
- 기존 클라우드 실행 잠금·분당 제한·TLS 검증·응답 크기/시간 제한을 공유한다. 리디렉션·환경 프록시·자동 재시도는 사용하지 않는다.
- 사용량이 반환되면 입력/출력 토큰을 표시한다. 토큰 수는 실제 청구 크레딧·잔액 확인을 대신하지 않는다. 과금과 데이터 보관 조건은 빌링AI 및 선택 공급사의 정책을 따른다. 무보관·학습 미사용을 보장하지 않는다.

## 확인한 공식 자료와 시험 범위

2026-11-03 [공식 Responses 문서](https://billing-ai.doublezero.kr/docs/responses)에서 `/api/v1/responses`와 `text.format.type=json_object` 지원, 완료/미완료 상태와 사용량 형식을 확인해 의미 검사에 적용했다. JSON 객체 출력 요청은 문법 오류를 줄이기 위한 생성 제약이며, 검사 스키마·출처·인용·의미 정확성을 보장하지 않는다. 서버는 JSON 객체와 기존 검사 계약을 계속 검증하고 미완료·거절·도구 호출·손상 응답은 거절한다. 지원 오류가 나더라도 다른 경로로 자동 재요청하지 않는다. 이번 변경에 대한 실제 계정·모델별 JSON 출력 보장은 추가 실제 실행으로 확인해야 한다.

2026-10-10에 [빌링AI API 개요](https://billing-ai.doublezero.kr/docs), [텍스트 API](https://billing-ai.doublezero.kr/docs/text), [모델별 예시](https://billing-ai.doublezero.kr/models/gpt-5-4)를 확인했다. API 개요/텍스트 문서는 `.doubleze.ro`를 사용하며 일부 모델 상세는 `.doublezero.kr` 예시를 제공한다. RubriQ는 개요의 고정 `.doubleze.ro` 주소를 사용한다. 인증 정보 없는 HEAD 요청으로 해당 경로의 TLS 접속과 HTTP405/Allow: POST, OPTIONS를 확인했다. 이는 실제 추론 성공 시험이 아니다.

실제 키가 없어 개발·브라우저 시험은 합성 문서와 모의 공급사 응답으로 수행한다. 인증된 호출, 계정 권한·크레딧·선택 모델 품질/지연은 사용자 키를 입력한 실제 실행에서 별도 확인해야 한다. 공개 모델 목록은 변경될 수 있으며 모든 모델의 RubriQ JSON 응답 호환성을 검증한 상태가 아니다.
# TLS와 응답 대기시간

클라우드 연결은 Python 기본 신뢰 루트에 프로젝트 의존성 `certifi`의 Mozilla 루트를 추가한다. 서버 인증서와 호스트명 검증을 유지하며 인증 실패를 우회하지 않는다. 로컬 Python에 루트 인증서가 없어 발생하던 연결 실패를 예방한다. 인증서 검증 실패는 `cloud_tls_failed`로 반환하며 비밀정보나 공급자 원문 오류는 반환하지 않는다.

클라우드 의미 검사(요구사항 추출·보고서 비교)의 HTTPS 소켓 작업 시간 제한은 180초, 선택 문구 윤문은 60초다. 이 값은 전체 실행의 엄격한 총 시간 제한이 아니다. 시간 초과 후 공급자 처리가 계속되었을 수 있으므로 자동 재시도하지 않는다. 사용자가 전송 범위를 다시 확인하고 동의해야 재요청한다.
