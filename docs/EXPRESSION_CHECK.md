# RubriQ 로컬 한국어 표현 점검

## 범위와 출처

사용자가 선택한 원문 구간 또는 현재 구조 블록만 점검한다. 문서 전체 검사, AI 작성 여부 판별, 요구사항 충족 판정, LLM 윤문은 이번 기능에 포함하지 않는다. 사용자가 2026-10-10에 로컬 진단부터 연결하는 방식을 선택했다.

출처는 [epoko77-ai/im-not-ai](https://github.com/epoko77-ai/im-not-ai), 고정 커밋 `2f3d943d08056b612a92e12bfb72ea94dd2acd18`이다. 저장소의 전체 스킬을 자동 실행하거나 전역 설치하지 않고, 검토한 로컬 계수 함수와 규칙을 제한적으로 연결한다. 정확한 포함 파일·추출 함수·해시는 vendor의 PROVENANCE와 LICENSE에 기록한다. MIT 저작권/허가 고지는 보존한다.

현재 위치별 후보 규칙은 A-7 가지다·만들다 표현, A-8 이중 피동, A-9 행위자와 피동 결합, A-19 겹친 조사, D-1 결론 연결 표현 반복이다. D-1은 선택 구간에서 결론 연결 표현이 네 번 이상일 때 안내하는 RubriQ의 보수적 정책이다. 원본 계수 함수 여섯 개를 직접 실행하며, 겹친 표면형이 중복 집계될 수 있다. 전체 85개 패턴을 검사했다고 표현하지 않는다.

## 결과의 의미

- 계수는 표현이 나온 횟수다. AI 작성 확률이나 품질 점수가 아니다.
- 원문 위치가 확인된 표현만 문제 후보로 표시한다. 보고서에서 해당 표현이 적절할 수도 있으므로 문맥을 확인한다.
- 직접 인용은 자동 수정 대상으로 제안하지 않는다. 수치·날짜·고유명사를 바꾸거나 원문을 덮어쓰지 않는다.
- 참고 제안은 사용자가 검토할 힌트다. 바뀐 문서를 생성하거나 수정안을 자동 적용하지 않는다.
- 발견된 후보가 없어도 글의 정확성·자연스러움·요구사항 충족을 보장하지 않는다. 지원 규칙과 읽은 범위의 제한을 표시한다.

## 세션과 원문 연결

`POST /api/document-pairs/{session_id}/{role}/expression-check`는 기존 세션 토큰과 블록 ID·문자 시작/끝 위치를 사용한다. 서버가 세션의 원문을 읽어 범위를 검증하며 임의의 외부 원문을 요청으로 받지 않는다. 결과는 원본 문서 해시와 블록/선택 범위에 연결한다. 문자 위치는 Python Unicode 코드포인트 기준이고, 브라우저 UTF-16 위치는 변환한다.

최대 선택 길이는 20,000자, 최대 반환 후보는 100개다. 초과·원문 부재·잘못된 토큰·만료·엔진 오류는 안전한 오류로 반환한다. 기존 로컬 Host/동일 출처 검사, 요청 제한, `no-store`를 적용한다. 결과는 저장본 계약에 추가하지 않고, 역할/블록/세션을 바꾸면 화면의 이전 결과와 진행 요청을 정리한다.

## 검증과 후속 작업

합성 한국어 자료로 함수 실행, 원문 위치, 인용 보호, 빈 결과, 길이 한도, 인증·만료·실패 복구·오래된 응답·모바일/키보드를 검증한다. 공개된 실행·지원 범위와 시험 방법은 [README](../README.md)를 따른다.

AI 윤문은 별도 제공자/모델 설정, 외부 전송 동의, 원문과 수정본의 사실·인용 검증 및 사용자 채택 흐름을 갖춘 후 연결한다. 로컬 표현 진단을 전체 스킬 실행 완료나 AI 의미 검사 완료로 기록하지 않는다.
