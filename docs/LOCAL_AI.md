# RubriQ 로컬 AI 실행

RubriQ 자체 코드는 Apache License 2.0이다. 포함된 제삼자 코드와 외부 실행 도구는 각자의 라이선스를 유지하며 `../THIRD_PARTY_NOTICES.md`를 참고한다.

## 현재 제공하는 기능

Ollama의 설치된 로컬 모델로 선택 문구의 한국어 윤문 제안을 생성한다. 원본은 읽기 전용이며 제안은 별도로 표시한다. 윤문 기능은 요구사항 충족 판정·AI 작성 여부 판정·자동 수정·결과 영구 저장을 제공하지 않는다. 안내문과 보고서의 비교에는 별도의 [요구사항 확인 후 AI 검사](SEMANTIC_AI.md)를 사용할 수 있다. 사실·수치·인용이 유지되는지 사용자가 직접 확인해야 한다.

Gemini·OpenAI·Anthropic 연결은 별도의 클라우드 패널에서 제공한다. 해당 API 사용 시 선택 문구가 외부 제공자로 전송되며 사용자 소유 키와 전송 범위 확인이 필요하다. 제공자 간 자동 전환은 하지 않는다. 사용 방법과 제한은 [CLOUD_AI.md](CLOUD_AI.md)를 따른다.

## 실행 방법

1. Ollama를 별도로 설치하고 원하는 모델의 사용·배포 조건과 하드웨어 요구사항을 확인한다. RubriQ는 모델을 설치하거나 다운로드하지 않는다.
2. 기존 설치 모델을 사용해 Ollama를 아래와 같이 실행한다. 같은 포트를 사용하는 기존 Ollama가 있다면 먼저 그 서비스의 설정을 확인한다.

```sh
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 ollama serve
```

3. RubriQ `/prepare`에서 문서를 준비하거나 저장본을 다시 연다. 로컬 AI 패널에서 모델 목록을 확인하고 원문의 문구를 선택한 뒤 윤문 제안을 요청한다.

설치 모델이 없다면 모델 없음 안내가 표시된다. 모델 다운로드는 사용자가 Ollama에서 별도로 수행한다. 모델 가중치의 라이선스는 RubriQ의 Apache 라이선스와 별개다.

## 데이터와 실행 경계

- RubriQ 백엔드는 고정 주소 `127.0.0.1:11434`만 호출한다. 브라우저가 임의 주소를 지정하지 못하며 프록시·리디렉션을 사용하지 않는다.
- 설치 모델 목록과 선택 모델의 정보를 확인하고 원격/클라우드 모델은 거부한다. 사용자 관리 Ollama 서비스와 모델의 신뢰성까지 RubriQ가 보증하지는 않는다. 클라우드 기능을 끈 Ollama로 실행하는 구성을 권장한다.
- 선택 문구 최대 4,000자만 모델 입력으로 보내고, 파일 접근·셸 실행·웹 탐색 도구는 제공하지 않는다. 요청은 자동 실행하지 않는다.
- 세션 토큰과 로컬 전용 요청 헤더를 검사한다. 제안은 원문 해시와 문자 범위에 연결하고 문서 전환 이후 도착한 응답은 표시하지 않는다.
- Ollama 요청에 시간·응답 크기·동시 실행 제한을 적용한다. UI 취소나 연결 해제만으로 Ollama의 추론이 즉시 중단된다고 보장하지 않는다.
- RubriQ는 원문이나 모델 응답을 오류 로그에 출력하지 않는다. Ollama 자체 로그·저장 동작은 사용자의 서비스 설정에 따라 달라질 수 있다.

## 인터페이스

`GET /api/document-pairs/ollama/models?session_id=...`는 세션 토큰과 `X-Local-Client: prepare`로 설치 모델 목록을 조회한다.

`POST /api/document-pairs/{session_id}/{role}/ollama-rewrite`는 동일 헤더와 `{block_id, start, end, model}`을 받는다. 서버가 원본 구조에서 선택 범위를 다시 읽으며 응답은 원문 해시·블록·범위·원문·윤문 제안과 실행 모델을 포함하는 기존 envelope를 사용한다.

공식 API: [모델 목록](https://docs.ollama.com/api/tags), [대화 생성](https://docs.ollama.com/api/chat). 구현은 비스트리밍 응답을 사용한다.
